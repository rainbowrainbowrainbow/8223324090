Нові SQL-тести включені до штатних `finance` і `payroll` runner; чинний CI виконує їх на disposable PostgreSQL. Зміни CI workflow не потрібні.

## Доставка й перевірка

Штатна послідовність: functional commit → version/cache/changelog commit → повний `npm test` → exact-SHA production push → всі вісім обов'язкових CI jobs → `npm run release:railway-up` → exact-SHA live proof та read-only smoke.

Старий controller workflow `finance-manual-qa` призначений для першого SQL/journal-релізу та вимагає міграції 381/382 у diff. Для цього пакета без SQL він не використовується; його allowlist, policy, FIN03 renewal та історія спроб не змінюються. Доставка використовує документований Railway release helper із ручною перевіркою всіх обов'язкових CI jobs, меж поточного погодження та exact SHA. Жодні skip/override flags не допускаються.

Обов'язкові CI jobs: Fast baseline, Omni browser regression, Certificate redemption regression, Checkbox park PostgreSQL mock integration, HR Team browser smoke, HR and payroll PostgreSQL integration, My Day PostgreSQL integration, My Day browser interactions. Pending, failed або skipped не є успіхом.

База сумісного повернення — поточний live SHA `9667c381781e83f6a484f3718ad6c36a2ac07fc9`. У разі регресії готується вузький зворотний функціональний коміт з наступним patch через ті самі перевірки й helper. Журнал, міграції та guards 381/382 зберігаються; force-push, downgrade схеми та перезапис історії заборонені.

## Що реліз сам по собі не доводить

Потрібні окремі докази для історичної різниці 795/485 тис., повної звірки оплат/боргів/повернень, немаркованих тестових записів і неповної історії угод. Приймання кількох кас та Checkbox потребує наявного належного тестового доступу й окремого погодженого обсягу операцій. Не можна оголошувати їх виконаними лише за успішним deploy.
