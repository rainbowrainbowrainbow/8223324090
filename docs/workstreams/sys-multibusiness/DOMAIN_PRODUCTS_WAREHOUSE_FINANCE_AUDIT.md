Date: 2026-09-12. Base: `a5180def01a1e47f8f4fc75e2f7a43092f205828` in the existing `codex/sys-mb-auth-p0-20260912` worktree. This audit and bounded patch preserve the earlier auth/lifecycle/WS/profile checkpoint. No schema, prices, formulas, finance/payroll code, provider configuration, production data, or deployment was changed.

`supported` below describes the inspected source boundary, not certification of every domain endpoint or live QA. The whole multi-business domain cutover remains blocked by the explicit residuals.

## Fixed in this patch

1. **Fallback catalog count included other businesses.** With no global graduation catalog definition, `/api/products/catalogs` previously counted every active graduation package. `routes/products.js:1378` now binds `business_context` to the already authorized context. PostgreSQL fixtures include active Park, Dar and a third-organization business; only the one active Park row contributes.
2. **Photo intake could restock any known stock ID.** `services/warehousePhotoIntake.js:637` now locks stock only within legacy Park; the UPDATE at `:650` repeats the same ownership predicate. This covers both client-supplied stock IDs and cached matching candidates. A missing/foreign stock returns 404 with no durable mutation.
3. **Photo intake could attach a foreign location or rely on default ownership.** `services/warehousePhotoIntake.js:613` checks draft and existing stock locations before mutation. New stock, history and movements at `:662`, `:685`, `:693` write the explicit context. Tests deliberately give database columns the wrong default to prove that ownership does not rely on defaults.
4. **Global intake rows were exposed as if membership-scoped.** The route guard explicitly quarantines the unsupported feature. The service also rejects a non-Park `options.businessContext` before connecting; it never reassigns a global intake to Dar or another business. No intake ownership was invented or backfilled.
