# G1: локальний OCR — синтетична перевірка

Дата: 2026-09-11. **LIMITED: цифри розпізнаються; безпечна автоматична адресація не доведена.** Production impact: no.

Створено й запущено [Test-LocalOcr.ps1](Test-LocalOcr.ps1). Використано вбудований Windows.Media.Ocr, language en-US; на машині доступні en-US і ru. Нові залежності/мовні пакети не встановлювалися. Метод RecognizeAsync працює із SoftwareBitmap; використані офіційні [опис API](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine.recognizeasync) і [опис рушія](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine).

## Метод

Зображення 480×120 генеруються в RAM: Segoe UI 12/16/24 px, dark/light фон, однакова synthetic назва та два зарезервовані приклади +12025550100 / +12025550101. Це номери для документації, не справжні тестові акаунти. Є 12 позитивних випадків і 4 негативних: два номери в кадрі, відсутній номер, відсутній плюс, номер частково закритий фоном. Для обрізання прямокутник закриває праву частину рядка, не змінюючи решту зображення.

Кожен випадок перевірено без масштабування, із 2× і 3× bicubic збільшенням початкового bitmap; текст не перемальовується більшим шрифтом. Це три варіанти тих самих 16 fixtures, не 48 незалежних прикладів реального Viber. OCR line text та отримані кандидати залишаються в RAM; JSON містить лише case IDs і boolean результати. Зображення не записуються на диск; Viber не читається і не керується цим скриптом.

Extractor приймає тільки окремий рядок із `+`, цифрами та дозволеними роздільниками, вимагає рівно один кандидат; прибирає лише пробіли, дужки й дефіси. Не підміняє O/0 або I/1. П’ять незалежних parser checks пройдено. Кожна OCR async operation очікується до 10 секунд; це не перевірений end-to-end watchdog усього процесу. При runtime exception сценарій має error=ocr_case_failed, а текст винятку не друкується.

## Фактичні результати

| Scale | Точні позитивні номери | Правильно відхилені негативні | Усього пройдено | Небезпечна помилка |
|---|---|---|---|---|
| 1× | 4/12 | 4/4 | 8/16 | Не виявлено в цих fixtures; 12/16 px не дали кандидата |
| 2× | 12/12 | 3/4 | 15/16 | Обрізаний номер прийнято як коротший кандидат |
| 3× | 12/12 | 3/4 | 15/16 | Обрізаний номер прийнято як коротший кандидат |

Докази: [1×](G1_OCR_SYNTHETIC_X1.json), [2×](G1_OCR_SYNTHETIC_X2.json), [3×](G1_OCR_SYNTHETIC_X3.json). Усі три запуски мають status=synthetic_fail; exit code тестового скрипта 1 — очікуване відображення провалених сценаріїв, не успішний gate. Винятків OCR у цих запусках не було. Після 2× і 3× позитивні A/B не переплутані, але ця маленька вибірка не оцінює production error rate.

## Наслідок для моста

Windows OCR придатний як кандидат на локальний extraction engine із 2× preprocessing. **Phone-like regex не є доказом правильного номера.** Негативний clipping test провалено у двох масштабах; сама повторна обробка різними масштабами не гарантує захисту від цього класу помилок. Рівність фактичних обрізаних рядків між масштабами не перевірялася й не заявляється.

Для наступного контрольованого тесту потрібні одночасно:

1. Перевірена область identity відкритого чату, повний видимий рядок, відсутність overlay і завершений перехід. Пошук номера в тілі повідомлення не підходить.
2. Порівняння отриманого повного номера з наперед відомим expected peer. `candidate_present=true` без exact match не дозволяє Send. Exact match — необхідний, але не достатній: потрібен доказ джерела й актуальності кадру.
3. Окреме правило unknown/new contact: немає expected peer, тому автоматична прив’язка лише за OCR поки непридатна. Потрібне надійне незалежне джерело identity або ручна перевірка з чесним статусом LIMITED.
4. Синтетичні B/C з однаковими назвами, rename, 30 почергових відкриттів, D із першим зверненням, resize/overlay і спеціально обрізані кадри. Без справжніх контрольованих акаунтів це NOT RUN.

Не включено: screenshots реального Viber, реалізація live capture/crop, OCR кириличних імен, confidence calibration, journal/HTTPS/send, restart/lock/RDP, receipt/delivery, фото/PDF. Перевірка рушія не є прототипом двостороннього personal bridge. G1 лишається неповним.
