# Omni — стан реалізації та підключення каналів

Оновлено 11.09.2026. Production impact: yes під час випуску. Цей документ
не є дозволом на реальні повідомлення, платні SMS чи зміну налаштувань провайдерів.
Діалоги ведуть люди. SMS-fly збережено сумісним, його активація не входить у роботу.

## Реалізовано та перевірено

| Канал | Реалізовано | Автоматична перевірка | Наживо | Зовнішня залежність |
|---|---|---|---|---|
| Telegram | Бізнес-ізоляція, власник webhook, текст, JPEG/PNG/PDF, архів вхідних файлів, діагностика, захист повторів | Підпис/secret, fixtures приймання й відправки, multipart, PostgreSQL і конкурентні повтори, UI | Підключення, поточний webhook, сторінка та історія прочитані тестовим акаунтом; нову відправку файлу наживо не виконували | Погоджений тестовий діалог для фото/PDF та двох менеджерів |
| Viber | Підписані webhook, текст, фото/PDF, receipts, канонічний setup з правом керування | Provider fixtures, повні числові ID, відмова до API за неправильного доступу/URL, обмеження файлів | Не підключений | Активний бот, токен, тестовий користувач/підписка |
| TurboSMS | Вихідний текст, callbacks, перевірка статусу за ID без повторної відправки, ручна звірка | Статуси, невідомий результат, відповідність ID/номера/типу SMS, дублікати callbacks | Не підключений; SMS не надсилали | HTTP API, дозволений відправник, callback, тестовий номер і бюджет |
| Facebook | DM, файли, коментарі, postback, quick reply, окремі публічна/приватна відповіді | Підписані події, дедуплікація, ізоляція, окремі запити відповідей | Не підключений | Page, застосунок, Page token, дозволи та підписки; звичайний тестовий користувач |
| Instagram через Facebook | DM, зображення, коментарі/посилання на допис, postback/quick reply, окремі відповіді | Linked Page/IG identity, підписані події, маршрутизація та формат запитів | Не підключений | Professional Instagram, пов'язана Facebook Page, ID обох, Page token, дозволи та підписки |

Fixtures доводять контракт нашого коду, але не підтверджують видані провайдером
дозволи, перевірку застосунку або доставку кінцевому користувачу. Meta залишається
«Обмежено», доки перевірено лише токен: це свідомо не називається готовим прийманням.
Вхідні SMS не обіцяються без окремої послуги провайдера.

## Спільні сценарії

- Webhook ownership: PostgreSQL серіалізує конкурентне підключення одного Telegram
  бота; Report/legacy не перехоплюють власника Omni. Помилка перевірки блокує зміну.
- Діагностика: збережені перевірка/помилка/час приймання, журнал без текстів і токенів;
  перевірка раз на п'ять хвилин, застарівання після 15. Порожній inbox не є аварією.
- Менеджери: оновлення status/assignee у відкритому діалозі, CAS одного поля з 409,
  незалежні зміни різних полів; чернетки та вкладення ізольовані між діалогами.
- Файли: PostgreSQL bytea, JPEG/PNG/PDF до 10 МБ, менші ліміти каналів; SMS без файлів,
  Instagram без PDF. Перевіряються сигнатура, тип і розмір. Менеджер читає файл через
  доступ до розмови; провайдер отримує годинний дозвіл на один файл. Вхідні URL
  перевіряються проти SSRF; помилка архівації видима окремо. Не додавався брокер повторів.
- Невизначена доставка: перевірка TurboSMS не викликає send; без ID/receipt лишається
  unknown. Ручна звірка має автора, час та історію і не замінює підтвердження провайдера.
- Коментарі: явний вибір «Публічна відповідь» / «Приватне повідомлення», окремий
  ідентифікатор коментаря; непідтримувані Meta-події фіксуються в діагностиці.

## Порядок активації та критерії

1. **Telegram: підтвердити нові можливості.** Один погоджений тестовий діалог,
   два тестові менеджери. Вхідний текст і JPEG/PDF → Omni → відповідь/файл → Telegram;
   повторний клік і reload не дублюють повідомлення. Перезапуск не втрачає файл.
2. **Viber.** Надати доступ до активного бота локально; звірити його власника й
   канонічний callback бізнесу. Погодити тестового підписника. Перевірити вхідне,
   відповідь, фото/PDF і доступні receipts. Не перепризначати чужий webhook.
3. **TurboSMS.** Підтвердити HTTP API, відправника і callback зі спільним секретом.
   До першої SMS зафіксувати номер, максимальну кількість і суму в гривнях.
   Перевірити вихідну SMS, callback та status lookup без другого списання.
   Вхідні SMS — окремо після підтвердження послуги. Фото/PDF в SMS не показувати.
4. **Facebook, потім Instagram.** Звірити Page token, Page ID і пов'язаний IG ID.
   Перевірити доступи застосунку та webhook-підписки messages, messaging_postbacks,
   receipts і відповідні feed/comments. Для DM потрібні відповідні messaging permissions,
   для коментарів — comment permissions. Тестувати також користувачем без ролі в
   застосунку: DM в обидві сторони, файл, коментар, публічна та приватна відповіді.
   Приватні відповіді обмежені правилами Meta; відмова провайдера має бути видима.
5. **Фінальна перевірка менеджерів і телефонів.** Тестові PARK/DAR акаунти з уже
   чинними правами, два менеджери, unread/«Мої»/очікування/закриття/reopen.
   Android та iOS фізично: клавіатура, прокручування, picker, PDF/фото, назад до списку.

Для кожного живого сценарію зберегти: версію/SHA, канал і тестовий бізнес,
час, provider message ID (без текстів і секретів), результат приймання/відповіді,
доступний статус, файл після reload та кількість повторів. Невдалий тест не позначати
як успіх через зелені fixtures.

## Ще не підтверджено

- Фізичні Android/iOS та системна клавіатура: Chrome viewport 390px цього не доводить.
- DAR наживо: поточний тестовий акаунт отримує 403; права не розширювали.
- Реальна відправка/приймання нових вкладень і Meta-подій; provider URL доступність
  та фактичні permissions перевіряються лише після погодження тестових адресатів.
- Активація Viber/TurboSMS/Facebook/Instagram: доступи не надані в цій задачі.
- Facebook private reply та всі Meta API-запити перевірені fixtures; сумісність із
  конкретним застосунком/дозволами залишається окремою live-перевіркою.

## Первинні джерела для оператора

- [Telegram Bot API](https://core.telegram.org/bots/api): multipart photo/document.
- [Viber REST Bot API](https://developers.viber.com/docs/api/rest-bot-api/): webhook,
  розміри та формати повідомлень. Для зображень CRM застосовує 1 МБ для сумісності клієнтів.
- [TurboSMS API](https://turbosms.ua/ua/api.html): callbacks та `message/status.json`.
- [Meta Messenger Platform](https://www.postman.com/meta/messenger-platform-api/collection/iyp204x/messenger-platform-api)
  та [Meta Instagram API](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api):
  Page-linked підключення, DM, comments/private replies та permissions.
