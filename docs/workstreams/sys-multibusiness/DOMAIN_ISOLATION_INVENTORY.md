## Reproduced defects fixed in this increment

1. **Cross-business employee directory/assignment (P1).** `/api/tasks/owners` and `/api/leads/assignees` queried global users/roles; an employee with a strong global role or stale legacy context mirror could be selected in the wrong business. The SQL now checks active account, organization, business, organization membership and business membership; returned role is from that business. Task department/self policies still apply. Actual PostgreSQL and same-JWT revocation tests cover these boundaries.
2. **Cross-business related-record projections (P1).** Customer and lead communication views matched global conversations by customer/phone/name. Lead product joins and client review/child projections could expose labels from an inconsistent historical link. Business and parent identity predicates now restrict these reads. New product/booking/mailing references are checked before mutation.
3. **Timeline implicit Park context and settings capability (P1).** `timelineContextFromRequest` manufactured Park without an explicit context; it now follows authenticated active membership. Park/Dar settings had no entry in the special-context role map and implicitly succeeded; the current `manage_settings` capability now applies. Ticket quote keeps the user context and rejects conflicting query/header context before pricing SQL. Four unit regressions were reproduced before the patch, then passed unchanged.
4. **Warehouse intake target ownership (P1).** Legacy confirm selected/updated stock by ID only and could refer to another business's location. Scoped lookups and transaction writes prevent this. Global intake drafts still lack ownership; membership access is explicitly denied instead of assigning old drafts to a business.
5. **Graduation fallback count (P2).** Fallback `/api/products/catalogs` counted all active packages. The count now uses the requested business, including an empty result.
6. **Defensive internal compatibility lookup (P2).** A compatibility actor could pass an inaccessible context absent from its registry snapshot to the reusable candidate helper and receive legacy SQL. The helper now checks the actor's existing context policy before that fallback. No reachable HTTP exploit was found because request auth loads the requested target independently.
