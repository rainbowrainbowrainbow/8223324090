# WhatsApp: достовірний стан прийому

Задача OMNI-WA-STATUS-CLOSE, 21.09.2026. Production impact: yes.

## Відтворена причина

Live baseline: `v0.82.2`, `f2e4dac078838165cf96e0e28db2dd140337b473`,
`codex/eventgenix-production`. PARK: `connected=true`, `sendCapable=true`,
`receiveCapable=false`, `status=limited`. Підключення збережене в БД;
останнє вхідне повідомлення 21.09.2026 було пізніше останньої зміни конфігурації
17.09.2026; помилок обробки немає. Health і база справні.

Перевірка Phone Number ID підтверджувала лише доступ до Graph API й повертала
`partial`. Account status і відповідь recheck не враховували прийнятий inbound.

## Виправлення

- Статус WhatsApp узгоджує перевірку провайдера, останню зміну збереженого
  підключення, прийняте вхідне повідомлення та нові помилки webhook.
- Прийом підтверджується лише повідомленням після зміни конфігурації і
  успішною/частковою перевіркою провайдера для цієї конфігурації.
- Повторний recheck та GET повертають узгоджений стан; тиша в діалозі не
  скасовує факт прийому. Давність перевірки залишається окремою діагностикою.
- Нова помилка обробки, недійсний токен, недоступний провайдер чи зміна
  конфігурації не приховуються старим успішним прийомом.
- Receipt не підтверджує inbound і не очищає помилку прийому WhatsApp.
- Бізнес-контекст використовується при читанні та записі діагностики.

## Перевірки та межі

Node 22.23.1 / npm 10.9.8. Targeted tests: 68/68, включно з повторним
recheck → GET, помилками, зміною підключення, receipt та ізоляцією бізнесів.
Нові тести включено до стандартного CI test:unit. До виправлення регресії
підтвердили неправильний limited і очищення помилки одним receipt.

Environment-only підключення без дати зміни конфігурації не отримують
автоматичного підтвердження за старою подією. PARK використовує database binding.
Схема БД, налаштування Meta, secrets, номер, auth та ролі не змінюються.
Live QA обмежений статусом і штатним recheck: повідомлення не надсилаються.
Перевірка довговічності токена й доставки фото/PDF лишається окремою задачею.

Точні release SHA, CI та результати live QA фіксуються у фінальному звіті
цієї задачі після релізу; локальні fixtures не доводять live-доставку.
